## 宿題

- **取り組んだレベル：** 基礎

- **やったこと：**

  第4回の基礎課題として、採点ルーブリックの文言を変更し、LLMによる採点結果がどのように変化するかを検証した。

  具体的には、`data/eval/rubric.md`の「分かりやすさ」の基準を1か所変更し、軽微な言い換えや繰り返しがあっても、回答が明確で理解しやすければ合格とする方針にした。

  採点モデル、temperature、評価用の10ケース、自分が付けたラベルを固定し、`uv run python -m app.judge`で変更前後の比較を行った。

- **結果：**

  | 評価項目 | 変更前 | 変更後 |
  |---|---:|---:|
  | 根拠 | 8/9 | 9/9 |
  | 範囲 | 10/10 | 10/10 |
  | ヒント | 10/10 | 10/10 |
  | 分かりやすさ | 9/10 | 10/10 |
  | 回の表示 | 9/10 | 9/10 |
  | 総合一致率 | 8/9 | 8/9 |
  | 要確認件数 | 1件 | 1件 |

  基準別の一致率は「分かりやすさ」と「根拠」で改善し、不一致項目数は3件から1件に減少した。

  特に、#04の「分かりやすさ」について、当初はLLMが不合格、自分が合格と判定していたが、ルーブリック変更後には両者が一致した。

  ただし、総合一致率と要確認件数は変化しなかった。

- **気づき・疑問：**

  今回の実験から、LLMによる自動採点の精度は、使用するモデルだけでなく、ルーブリックの設計にも影響されることを学んだ。

  特に、採点基準を具体化することで、実際に判定の不一致を減らせることが確認できた。

  一方、評価基準の文言を変更していない項目でも判定が変わったため、今回の1回の比較だけで改善効果を断定することはできない。

  今後は、同一条件での反復採点による再現性の確認や、評価セットに含まれていない新しい質問での検証を行いたい。

  また、LLMの採点を人間の判断に近づけるだけでなく、どのような回答を合格とすべきかという評価基準自体の妥当性も検討する必要があると感じた。
